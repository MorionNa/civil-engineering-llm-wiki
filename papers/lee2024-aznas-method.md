# AZ-NAS 方法机制

> 返回 [[lee2024-aznas-analysis]] 总览

## 总览：四代理互补体系 + 非线性排序聚合

AZ-NAS 的核心思想是**用多个互补的零成本代理从不同视角评估网络架构，再通过非线性排序聚合选出在所有代理上都高分的架构**。所有代理分数在**单次前向+反向传播**中同时计算，不需要训练、不需要标签、不需要特殊的架构修改（如去除 BatchNorm）。

AZ-NAS 将网络分解为 **primary blocks** —— 一组包含不同类型操作和多路径的层的集合。对于 NAS-Bench-201 是 cell 结构，对于 ResNet 是残差块，对于 ViT 是 attention block。代理在 block 级别计算，再聚合到网络级别。

---

## 代理 1：Expressivity（表达力评分 sE）

### 直觉

一个好的网络在初始化时应该充分利用其特征空间——特征应该在各方向上均匀分布（各向同性，isotropy），而不是少数几个方向（PC）主导。如果发生了**维度坍缩**（dimensional collapse）——少数 PC 的解释方差占比过高——意味着网络的有效容量被浪费，容易产生死神经元（dead neurons）。

### 数学

对第 l 个 primary block 的输出特征 f_l ∈ R^{c×n}（c 维特征，n 个样本点）：

```
1. 中心化：     f̄_l(p) = f_l(p) - (1/n) Σ_q f_l(q)
2. 协方差：     V_l = (1/(n-1)) f̄_l f̄_l^T
3. 特征值分解： λ_l ← eig(V_l)
4. L1 归一化：   λ̃_l(i) = λ_l(i) / Σ_j λ_l(j)
5. 熵（块级）：  sE_l = Σ_i -λ̃_l(i) log λ̃_l(i)
```

当所有特征值相等时（完全各向同性），sE_l = log(c)，达到最大值。当只有一个特征值为 1 其余为 0 时（完全坍缩），sE_l = 0。

网络级表达力评分：`sE = Σ_l sE_l`

### 可视化理解

论文的 Figure 2 给出了一个直观的 2D 示例。特征（绿点）在 (a) 中沿某一方向分布 → 第一 PC 系数占比很大 → sE = 0.23。在 (b) 中均匀分布 → 两个 PC 系数几乎相等 → sE = 1.00。sE 越高，特征空间利用越充分。

### 关键洞察

sE 不需要 ReLU 非线性（区别于线性区域计数方法），也不要求手动操作（区别于 Synflow 需要去 BN），适用于任意 block 类型。

## 代理 2：Progressivity（渐进性评分 sP）

### 直觉

现代网络架构（ResNet、MobileNet、EfficientNet）的一个共同设计原则是：**后面的 block 更宽，特征空间更大**。因为这符合"浅层少维特征→低层纹理，深层多维护特征→高层语义"的直觉。sP 自动量化这个原则：如果网络沿深度方向上表达力持续增大，说明架构遵循了渐进式扩展的规律。

### 数学

```
sP = min_{l∈{2,...,L}} (sE_l - sE_{l-1})
```

取所有相邻 primary block 之间表达力差的**最小值**。如果所有相邻块的表达力差都至少为 δ，则 sP = δ。

### 关键洞察

传统 NAS 搜索空间需要人工设置宽度约束（如"stage 2 宽度 ≥ stage 1"）——sP 自动奖励遵循这个原则的架构而无需硬约束。高 sP 的网络天然具备渐进式特征扩展结构。

### 局限

ViT 的 attention 模块用高斯随机输入初始化时，所有 token 的注意力值相似 → 输出特征在空间中趋于聚集 → 块间特征空间难以区分 → sP 失效。这也是论文在 AutoFormer 实验中去掉 sP 的原因。

## 代理 3：Trainability（可训练性评分 sT）

### 直觉

深度学习中的一个经典结果是：梯度在反向传播中不消失也不爆炸的充要条件是**每层 Jacobian 的谱范数接近 1**（Miyato et al., 2018, ICLR 的谱归一化工作）。如果一个网络在初始化时梯度就能稳定传播，训练就更容易达到好的结果。

但问题在于——primary block（如 NAS cell）的 Jacobian 不是简单的线性层矩阵，包含多种操作和多条路径。AZ-NAS 用 Hutchinson 方法做了巧妙近似。

### 数学

**步骤 1：线性化近似**
将第 l 个 primary block 的前向传播近似为线性系统：
```
f_l = ψ_l(f_{l-1}) ≈ A_l · f_{l-1}
```
其中 A_l ∈ R^{c×c'} 是线性变换矩阵——它也就是该 block 的 Jacobian。

**步骤 2：Hutchinson 估计**
引入 Rademacher 随机向量 v ∈ R^{c×1}（每个元素等概率取 ±1）：
```
u = φ_l(v) ≈ A_l^T v      （φ_l 是 block 的反向传播函数）
```
利用 E[vvᵀ] = I 的性质：
```
E[u vᵀ] = E[A_l^T v vᵀ] = A_l^T E[v vᵀ] = A_l^T
```
实际中用样本平均估计：
```
A_l^T = (1/n) Σ_{p=1}^{n} g_{l-1}(p) g_l^T(p)
```
其中 g_l 是用 Rademacher 随机向量合成的输出梯度，g_{l-1} 是通过 PyTorch autograd 得到的输入梯度。

**步骤 3：谱范数惩罚**
```
sT = (1/(L-1)) Σ_{l=2}^{L} [-σ_l - 1/σ_l + 2]
```
其中 σ_l = ‖A_l‖₂（谱范数）。这个函数在 σ_l = 1 处取得最大值 0，对称地惩罚偏离 1 的情况（σ_l = 2 和 σ_l = 0.5 惩罚相同）。

### 关键优势

与已有的梯度-based 代理（SNIP、Grasp、Synflow、ZiCo 等）相比，sT 有几个独特的优点：
1. **不绑定可训练参数**：已有方法分析**权重的梯度**，无法处理非参数操作（如 average pooling）。sT 分析 block 的输入输出梯度，适用于任意操作。
2. **更快**：单次反向传播即可获得所有 block 的 sT，且与 sE/sP 同一次传播内完成。
3. **非操作相关**：sT 评估的是 block 整体的梯度传播，而不是单个卷积/FC 的权重重要性。

## 代理 4：Complexity（复杂度评分 sC）

### 直觉

最近的研究（ZiCo, Ning et al. NeurIPS 2021）发现，令人尴尬的事实是：**FLOPs 和 #Params 这两个最简单的"代理"经常比精心设计的零成本代理有更好的排序一致性**。AZ-NAS 正面承认这一点，直接将 FLOPs 作为一个正向代理使用。

### 数学

```
sC = FLOPs(network)
```

在搜索过程中，sC 偏好 FLOPs 较大的网络——但前提是在给定的计算预算 B 内。

### 设计哲学

传统 NAS 将 FLOPs 视为约束（"找精度高的且 FLOPs ≤ budget"），AZ-NAS 将其视为信号（"在预算内，FLOPs 越大→计算利用率越高→可能越好"）。这个转变看似微小，但在排序聚合时意味着 FLOPs 不是一个需要主动限制的因素，而是一个可以和表达力/渐进性/可训练性一起优化成正向相关信号的因素。

## 核心机制：非线性排序聚合 (Non-linear Ranking Aggregation)

### 为什么需要非线性

假设网络 A 在 4 个代理上的排名分别是 [1, 1, 1, 1000]，网络 B 的排名是 [250, 250, 250, 250]。

**线性聚合**（求和或平均）：A = 1003, B = 1000 → A 胜出。但 A 在复杂度代理上表现极差（排名 1000），说明它可能无法有效利用计算资源。

**AZ-NAS 的目标**：当一个代理排名很低时，它应该严重拖累最终分数——类似于"木桶效应"，最短板决定容量。

### 数学

```
sAZ(i) = Σ_{M∈{E, P, T, C}} log(Rank(sM(i)) / m)
```

其中 Rank(sM(i)) 是网络 i 在代理 M 上的排名（升序，最好=1，最差=m），m 是候选架构总数。

**对数函数的惩罚效应**：
- Rank=1 → log(1/m)
- Rank=10 → log(10/m) = log(1/m) + log(10)
- Rank=1000 → log(1000/m) = log(1/m) + log(1000)

从 rank 1 到 rank 10，惩罚增加了 log(10) ≈ 2.30；从 rank 10 到 rank 1000，惩罚增加了 log(100) ≈ 4.61。低排名被对数函数急剧惩罚。

回到上面的例子：
- A: log(1/m) + log(1/m) + log(1/m) + log(1000/m) = 4log(1/m) + log(1000)
- B: 4 × log(250/m) = 4log(1/m) + 4log(250)
- A - B = log(1000) - 4log(250) ≈ 6.91 - 22.08 = -15.17

→ **B 胜出！** 非线性聚合成功"阻止"了高排名代理掩盖低排名代理。

### 在进化搜索中的使用（Algorithm 1）

1. 初始化第一个架构 F₁
2. 每轮迭代：
   - 计算 F_i 的 4 个代理分数
   - 将 F_i 和分数加入历史集合
   - 对所有历史架构计算 AZ-NAS 聚合分数
   - 从 top-k 架构中变异生成新的候选架构 F_{i+1}
3. 最终选择历史中 AZ-NAS 分数最高的架构

这个设计的一个聪明之处：聚合每次基于**所有历史架构的完整排名**——随着搜索推进，排名估计越来越稳定。

## 效率分析

| 代理 | 所需传播 | 之前替代方案 | 替代方案速度 |
|------|---------|------------|------------|
| sE | 前向 | NASWOT（线性区域计数） | 36.9 ms |
| sP | 前向（复用 sE） | — | — |
| sT | 反向（与 sE/sP 同次传播） | TE-NAS（NTK） | 1311.8 ms |
| sC | 零计算 | — | — |

AZ-NAS 总计：42.7 ms/arch —— 只比最快的单代理方法（ZenNAS 19.9 ms, GradNorm 28.8 ms）慢一倍左右，但提供了 4 倍的信息量和远超所有方法的排序一致性。
