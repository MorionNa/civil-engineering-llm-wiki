# AZ-NAS 深度批判分析

> 返回 [[lee2024-aznas-analysis]] 总览

## 7. 贡献 (Contribution)

### 7.1 范式级贡献：从"设计更好的单代理"到"组装互补代理"

这是 AZ-NAS 最核心的贡献。之前的训练-free NAS 研究范式是：
```
找到一个理论洞见 → 设计一个代理来捕捉它 → 在 benchmark 上验证
例如：线性区域数 → NASWOT, NTK → TE-NAS, 梯度信号 → ZiCo
```

AZ-NAS 翻转了这个范式：
```
认识到单代理不充分 → 设计一组互补代理 → 非线性聚合 → 整体超越各代理之和
```

这类似于机器学习中从"设计更强基学习器"到"ensemble learning"的范式转换——而这个转换在训练-free NAS 中是首次被系统性地论证。Table 4 和 Table 5 的证据非常有力：任意两个 AZ-NAS 代理组合就超过多数 SOTA 方法，且 AZ-NAS 代理可以显著提升已有方法（ZiCo +0.16τ, Synflow +0.19τ）。

### 7.2 技术贡献：四个新颖代理的质量

| 代理 | 创新程度 | 评估 |
|------|---------|------|
| sE (Expressivity) | **中等** | PCA 熵检测各向同性在表征学习中已有应用（Cai et al. 2021），但用于 NAS 评分是新的。与线性区域计数相比，不要求 ReLU、更高效。 |
| sP (Progressivity) | **高** | 将"渐进式宽度扩展"这个架构设计经验原则量化为可微分的评分——**这是完全原创的**。之前没有 NAS 方法显式奖励深度方向上的特征空间扩展。 |
| sT (Trainability) | **中高** | Jacobian 谱范数本身不新（谱归一化，Miyato 2018），但 Hutchinson 近似 + 推广到任意 primary block + 与 NAS 评分的结合是新颖的。关键创新在于"不绑定可训练参数"的设计。 |
| sC (Complexity) | **低** | FLOPs 本身是已有知识，但**将其作为正向代理而非约束**的视角转换有工程价值。 |

### 7.3 方法论贡献：非线性排序聚合

`Σ log(Rank/m)` 这个公式极其简单——简单到令人怀疑是否太简单。但它的效果（NL vs L 在所有配置上领先 0.04-0.05τ）证明了这个选择是正确的。背后的"木桶效应"直觉——低排名代理不能被高排名代理"平均掉"——既直观又有效。这是一个可以被广泛引用的聚合技巧。

### 7.4 实证贡献

在 NAS-Bench-201、MobileNetV2、AutoFormer 三个性质差异极大的搜索空间上达到 SOTA，证明方法不是"在特定空间上调出来的"。特别是 MobileNetV2 上以 ~0.5 GPU 天的搜索成本超越 OFA（50 GPU 天），是对训练-free NAS 实用性的有力证明。

## 8. 核心知识点 (Core Knowledge Nuggets)

1. **特征空间各向同性作为架构质量信号**：PCA 特征值的熵越大 → 特征在各方向上越均匀 → 网络表征冗余小、容量利用率高 → 初始化质量好 → 训练后表现好。这为"初始化即命运"提供了量化工具。

2. **Jacobian 谱范数 ≠ 权重梯度范数**：许多训练-free NAS 方法分析权重的梯度（SNIP, Grasp, Synflow）——但权重梯度反映的是"哪些参数应该保留"，而 Jacobian 谱范数反映的是"信息能否稳定传播"——这是两个完全不同的维度。AZ-NAS 清醒地区分了这一点。

3. **代理互补性 > 代理强度**：sT 单独只有 τ=0.349，但和 sE+sC 组合后增量 +0.05-0.11τ——说明在代理 ensemble 中，**相关性低比绝对准确度高更重要**。这和 ensemble learning 中"多样性与准确性权衡"的理论一致。

4. **非线性聚合的普适性**：`log(Rank/m)` 比线性平均更适合"多维度综合评价"场景——因为当你关心的是"所有方面都不差"时，木桶效应优于均值效应。

5. **Hutchinson 迹估计的推广**：通过 `u = φ(v)`, `A^T ≈ E[u v^T]`，将原本用于矩阵迹的无偏估计推广到任意可微分复合函数的 Jacobian——这是一个有独立引用价值的计算技巧。

## 9. Negative Knowledge（失败知识 / 为何会失败）

### 9.1 对 ViT 的零-shot 评估存在盲区

**失败表现**：sP 代理在 AutoFormer 上被完全禁用，因为 ViT 的 attention 模块用高斯随机输入在初始化时产生**相似的 token 间注意力分布**——输出特征趋于聚集，块间特征空间无法可靠区分。这导致 sP 给不出有意义的渐进性信号。

**教训**：零成本代理的可靠性取决于**初始化时网络的前向行为是否有信息量**。如果初始化行为（用高斯输入）与架构的最终行为无关，代理就失效了。对于 ViT，attention 的 token 交互在有语义的 token 上才有差异——纯噪声 token 下所有 token 被同等对待。

**推广**：任何依赖初始化前向激活结构的代理（sE, sP, NASWOT）都可能对 attention-based 架构效果不佳。需要开发考虑 token 交互语义的替代指标。

### 9.2 Jacobian 线性近似的未讨论误差

**失败风险**：sT 的核心假设是 `f_l ≈ A_l f_{l-1}`——将 primary block 近似为线性系统。对于包含多个非线性操作（ReLU, GELU）和多路径并行/串行组合的 block，这个近似可能引入不可忽略的误差。

论文没有给出近似误差的理论界或经验估计。在最坏情况下（例如 block 中有非常非线性的操作如 Swish 或通道注意力），A_l 可能严重偏离真实 Jacobian，导致 sT 信号失真。

**验证方法（论文未做）**：可以比较 Hutchinson 估计的 σ_l 与真实 Jacobian 的谱范数（在小网络上用 autograd 精确计算），评估近似误差随 block 非线性的增长趋势。

### 9.3 高斯输入掩盖数据-架构交互

**根本局限**：所有 4 个代理都只用高斯随机输入（N(0,1)）计算。这意味着 AZ-NAS 只评估了**网络架构在初始化时的内在属性**——完全无法捕捉：
- 网络对真实数据分布的适配倾向
- 网络对不同数据增强策略的响应
- 网络的归纳偏置是否匹配目标任务的对称性

例如，一个对 ImageNet 很好的 CNN 架构可能对 CIFAR-10 也很好——但一个对医学影像特别好的架构可能需要特定的归纳偏置（如旋转等变性），这在纯噪声下完全不可见。

### 9.4 sC 代理的双刃剑

sC = FLOPs 的引入虽然提升了整体 τ，但也带来了一个微妙的问题：**如果搜索空间的 FLOPs 分布与真实性能高度相关，AZ-NAS 的高 τ 可能部分归因于 FLOPs 而非其他三个创新代理**。

从 Table 1 看，FLOPs 单独 τ=0.517-0.578 在 IN16-120 上甚至高于 sE alone (0.506) 和 sT alone (0.407)。从 Table 4 看，sE+sT+sC（τ=0.708-0.731）相比 sE+sT（未报告，但可以从 sE+sT+sC 与单代理差异估算）有显著提升。但如果 FLOPs 在特定搜索空间中与性能的相关性异常高（比如搜索空间设计的 bias），AZ-NAS 可能会高估自己的方法优势。

### 9.5 与搜索策略的耦合

AZ-NAS 的进化搜索（Algorithm 1）每次基于**历史累积的所有架构**重新计算全局排名。这意味着：
- 早期代理排名因为样本少而不稳定 → 可能引导搜索到次优方向
- 代理分数的计算依赖于相对排名而非绝对值 → 没法用代理分数做跨搜索空间的架构比较

这在实践中意味着 AZ-NAS 需要"热身"——前若干次迭代的聚合分数可能不可靠。

## 10. 可迁移知识 (Transferable Knowledge)

### 10.1 方法论可迁移

| 知识 | 可迁移到 | 应用场景 |
|------|---------|---------|
| 非线性 log-Rank 聚合 | 多目标 NAS、多任务学习评估 | 任何需要从多个可能矛盾的排名中选"全面优等生"的场景 |
| PCA 特征熵 (sE) | 网络初始化诊断、表征学习评估 | 检测训练前的维度坍缩风险、比较预训练模型的特征空间质量 |
| Hutchinson Jacobian 近似 | 网络分析、量化、剪枝 | 估计任意复合模块的梯度传播特性，不限于 NAS |
| 互补代理设计原则 | 任何评分系统设计 | 选择低相关性的多重指标比优化单个指标的收益更大 |
| 渐进性量化 (sP) | 网络设计空间分析 | 评估搜索空间中不同架构模板的自然倾向 |

### 10.2 工程实践可迁移

- **搜索时不去掉残差连接**：ZenNAS/ZiCo 在搜索时删除 residual → 训练时恢复，引入了搜索-训练不一致。AZ-NAS 证明不需要这个 hack——这是一条重要的工程经验。
- **42.7 ms/arch 是训练-free NAS 的实用速度基准**：比这个慢太多的方法（>200 ms/arch）在大搜索空间上不实用。
- **公开代码使用官方复现结果对比**：Table 1 中所有对比方法的结果都用原作者代码重新复现——这应该是 NAS benchmark 论文的标准做法。

### 10.3 概念可迁移

"代理互补性 > 代理强度"这个核心洞察可以迁移到很多领域：
- **AutoML**：多个弱超参选择策略可能优于单个强策略
- **模型评估**：多个弱评估指标（困惑度、BLEU、人类评分）的组合可能优于单个"黄金指标"
- **强化学习**：多个弱奖励信号的组合可能比单一稠密奖励更鲁棒

## 11. 研究机会 (Research Opportunities)

### 11.1 数据感知的零成本代理

**问题**：高斯输入 vs 真实数据——能否用极少真实样本（1-5 张）替代高斯噪声，以捕获数据-架构交互，同时保持 ~ms 级速度？

**可行路径**：
- 用 CIFAR-10 的 1 张图 + 简单的数据增强（翻转/裁剪）替代纯噪声
- 比较噪声 vs 真实数据下 sE/sT 的差异——差异本身可能是额外的架构质量信号
- 代价：需要加载数据集 → 增加 I/O。可以在搜索开始时一次性加载 5 张图到 GPU 常驻内存。

### 11.2 Transformer 专用的渐进性代理

**问题**：sP 对 ViT 失效——需要设计适合 attention 架构的"特征扩展深度监测"指标。

**候选方向**：
- **注意力熵的深度演化**：浅层 attention 应该关注局部（高熵→多 token），深层应该聚焦全局（可能低熵→少数关键 token）→ 深度上的熵变化趋势可能是质量信号
- **Token 多样性的深度变化**：用 token 间余弦相似度的分布随深度的变化替代 sE 差
- **参考**：[[training-free-nas-transformers]] 中的 hidden covariance 和注意力剪枝指标可能提供灵感

### 11.3 自适应代理权重学习

**问题**：4 个代理等权——但在不同搜索空间上，某些代理可能更重要。MobileNetV2 上 FLOPs 可能更关键，AutoFormer 上 sT 更重要。

**可行路径**：
- 在 NAS-Bench-201 上学习代理权重（因为有 ground truth）
- 将学习到的权重迁移到新搜索空间（zero-shot transfer of proxy weights）
- 或者用贝叶斯优化/进化算法自动搜索权重配置

### 11.4 Hutchinson 近似的误差分析

**问题**：论文未量化线性化近似在真实 cell 上的误差。

**可行研究方向**：
- 在小规模网络上用 autograd 精确计算 Jacobian 谱范数，与 Hutchinson 估计对比
- 研究误差随 block 深度、宽度、操作类型（ReLU 密集 vs 平滑激活）的变化
- 给出适用条件：什么类型的 primary block 下 Hutchinson 估计可靠？

### 11.5 跨搜索空间通用代理

**问题**：sP 在 ViT 上失效说明当前代理不是完全通用的。

**终极目标**（类似 [[eznas]] 的精神）：自动发现一组适用于任意搜索空间（CNN/ViT/MLP-Mixer/GNN）的互补代理。

**可行路径**：
- 用 EZNAS 的进化表达式树方法，但在适应度函数中强制"互补性"（最大化代理间预测差异 + 最小化与 ground truth 的误差）
- 或 meta-learning：在多个搜索空间上学习代理的参数化形式

### 11.6 从排序一致性到绝对性能预测

**问题**：AZ-NAS 只做相对排序（哪个架构比哪个好？），不做绝对预测（这个架构能达到多少精度？）。

**可行扩展**：
- 将 AZ-NAS 的聚合分数与 #Params/FLOPs 结合，训练一个简单的校准回归器
- 类似性能预测器（performance predictor）的思路，但用 AZ-NAS 代理作为特征——可能比直接用架构编码特征更有效
