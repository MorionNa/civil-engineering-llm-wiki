# SEAL/ExMechConv M0 - NO-GO

## Verdict

**NO-GO.** The candidate is stopped. Preserve the SEAL code and tests as a
diagnostic scaffold only; do not launch a remote preflight.

The local main-thread evidence was:

```text
python -m pytest -q tests/test_seal_exmechconv.py
7 passed, 1 warning
compileall: passed
```

These results establish only smoke behavior. Sol's read-only review found the
following hard blockers:

| # | Finding | Consequence |
|---:|---|---|
| 1 | `ETDPolynomialAction` is truncated Taylor exp plus constant `phi1`, not registered Chebyshev/Cayley/FOH; degree-2 has `|P2(i xi)|^2 = 1 + xi^4/4`. | Undamped modal energy can grow by construction. |
| 2 | The guard uses a one-edge row sum and omits global `B.T K_e B`, node degree, matrix coupling, and matrix damping. | `dt*actual <= 1` is not a stability certificate. |
| 3 | Matrix stiffness uses forward-block `A_jj`. | Only a central pair spring is covered, not a general 2D frame/matrix edge. |
| 4 | Owner IDs are only an ID map; no owner mask or halo synchronization for histories, forces, and node state. | Halo execution may advance an edge twice. |
| 5 | Forcing is `rho*(1+slope)`, not `rho+slope*(rho-rho_prev)`. | The slope gradient is inactive when `rho=0`. |
| 6 | Scalar stiffness comes from the construction graph; vector force is only `(-f,+f)`. | Graph/subgraph replacement and general endpoint-force matrices are unsafe. |
| 7 | Energy helper uses only linear reference energy, omits work/damping/nonlinear storage, and silently truncates short runs. | It cannot certify high-frequency stability. |

## Fallback

Use the V21 physical oracle and vectorized Newmark/RK4/FEM references. Retain
the frozen parent only as a legacy initial guess and error indicator. No SEAL
accuracy, high-frequency success, or remote readiness claim is permitted.
